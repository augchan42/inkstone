## Findings

### A. [low] The supervisor and follow-up snippets depend on `PID_FILE`/`EXIT_FILE` variables that the text says do not survive between calls, and the follow-up probe can print nothing

**Where:** `skills/codex-review/reviewer-backends.md:43-45`, `:268-275`, `:277-290`; `skills/plan-review-loop/SKILL.md:100-106`, `:114` · **Lane:** correctness

**Defect.** The run directory and file paths are created in the output-contract step (`mktemp -d`, `:43`), which is a separate step before dispatch. The supervisor block then uses `"$PID_FILE"` and `"$EXIT_FILE"`. The follow-up example (`:283-290`) does the same. Meanwhile, the surrounding text says later calls "never inherit shell variables" (`:280`, `SKILL.md:114`). Neither snippet shows these variables being assigned, or literal paths being substituted, inside the same invocation. The follow-up snippet also has no `else` branch.

**Impact.** Suppose an agent creates the run directory in one Bash call and runs either snippet verbatim in another, which is the exact model the text describes. In the supervisor, `printf … > ""` fails with "No such file or directory", but the script carries on because it has no `set -e`. The `wait` still happens, but no exit file is written. Under `:293-294`, a successful review is then rejected as a supervisor failure. In the follow-up probe, both `[ -f "" ]` tests are false and the call prints nothing. That is the "decorative watcher" the same section warns about at `:298-302`: a dead reviewer and a live one look identical. The supervisor's `$REVIEW_FILE` and `$OUT` have the same dependency, but those were pre-existing and are usually substituted by the agent. The two new variables are introduced by this delta, and the contradicting "never inherit shell variables" sentence is too.

**Suggested fix.** Add one line to each snippet that assigns the run directory paths, for example `RUN_DIR=/abs/path/from/mktemp; PID_FILE="$RUN_DIR/pid"; EXIT_FILE="$RUN_DIR/exit"`, and say "substitute the literal paths recorded at setup". Add `else echo "no PID/exit file in $RUN_DIR yet"; fi` to the probe so it always prints a line. Optionally add `[ -n "$PID_FILE" ] && [ -n "$EXIT_FILE" ] || { echo "status paths unset"; exit 2; }` to the start of the supervisor.

No other actionable introduced defects were found. The new agent definition, the AGENTS.md tree entry, the backend-3 rule and the Phase 2 cleanup path are consistent with each other and with the hook's phase contract.
