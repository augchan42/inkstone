## Findings

### [medium] opencode is labelled "cross-model" by default, though independence depends on the model actually chosen
**Where:** `skills/codex-review/reviewer-backends.md:20`, `skills/deliver-change/SKILL.md:83-84` (also `README.md` and `AGENTS.md`, which describe codex-review as a "cross-model" review across all backends) · **Lane:** contracts / correctness

The backend table says opencode is "cross-model; vendor depends on `-m`". deliver-change says "an opencode run is cross-model but not Codex". Both conflict with the rule in `reviewer-backends.md:13-15`: cross-model status "depends on the actual reviewer and author models, not the CLI name". opencode can run the same model, or the same model family, as the author. This review is an example: it ran through opencode on an Anthropic Claude model. If a Claude session authored the change, that is a same-vendor review and possibly a same-model one. **Impact:** deliver-change handoffs and codex-review artifacts can claim cross-model independence that the run did not provide. That is exactly the overstatement the "record tool and model" rule is meant to prevent. **Fix:** in the table, say opencode's independence is "depends on `-m` vs author model". In deliver-change, drop the blanket "cross-model" claim and tell the caller to classify independence by comparing reviewer and author models. If they match, label the run same-model, as backend 3 is.

### [medium] The "check source unchanged" requirement has no baseline step, and the subagent backend now needs unenforced write access
**Where:** `skills/codex-review/reviewer-backends.md:46`, `:197-200`; `skills/plan-review-loop/SKILL.md:108` · **Lane:** correctness / security

The output contract says "Check that the reviewed source state is unchanged before accepting it", but no step records the source state before dispatch. For uncommitted or `--staged` scopes, which are dirty trees by definition, there is then nothing to compare against afterwards. Before this diff, backend 3 subagents returned text and the caller wrote the file. Now each subagent must "write its findings there under the same source-protection contract". Subagents in Claude Code have unrestricted Edit/Write, so for this backend the contract is honour-system only. Codex has `--sandbox read-only` and opencode has a scoped `edit` policy, but subagents have no equivalent. **Impact:** a fallback reviewer that edits source, for example by "helpfully" applying a fix, is not detected. The modified tree is then triaged and committed as though it were the reviewed state. **Fix:**
- Require a baseline before dispatch: `git rev-parse HEAD`, plus `git status --porcelain=v1 -z`, plus a hash of `git diff HEAD --binary` and the plan file. Compare these after the run, and treat any difference as a backend failure.
- For backend 3, either have subagents return text and let the caller write the lane reports, or restrict their tools.

### [medium] The guard loop's `pgrep -f` pattern matches the watcher's own shell, and now also matches unrelated `opencode run` processes
**Where:** `skills/codex-review/reviewer-backends.md:227` · **Lane:** correctness

`while pgrep -f "codex --sandbox read-only exec|opencode run" ...` runs inside a shell whose command line contains that literal pattern. Both alternatives therefore match the watcher's own `bash -c` process, so the loop never ends. The `codex` half was already present in the old SKILL.md, so that part is pre-existing. The new `opencode run` alternative adds a second problem: it matches every `opencode run` on the machine. That includes other users' or sibling sessions' reviewers, and an orchestrator that is itself running under `opencode run`. **Impact:** the watcher hangs, or reports "still running" after the reviewer it launched has exited. This is the "decorative watcher" failure the same section warns about. **Fix:** watch the launched PID, not a pattern. Capture `PID=$!` at launch and loop `while kill -0 "$PID" 2>/dev/null; do sleep 20; done`. If a pattern is unavoidable, make it unable to match itself (for example `[c]odex --sandbox`) and scope it to the launched PID.

### [medium] The opencode reviewer policy grants read access to the whole filesystem
**Where:** `skills/codex-review/reviewer-backends.md:134` · **Lane:** security

`"external_directory": "allow"` lets the reviewer read any path outside the worktree, such as `~/.ssh`, `~/.aws`, `.env` files in other repos, and other sessions' data. The reviewer reads untrusted diff content, for example an external PR. A prompt injection in that diff can steer it to read secrets and copy them into the assigned report. That report may later be committed (codex-review Phase 6, step 3), and in any case the secrets reach the model provider. The only external path the backend needs is the materialized diff. **Impact:** the read scope is much broader than the stated "report-scoped" least-privilege design, and it is reachable from attacker-controlled input. **Fix:** scope the permission as `"external_directory": {"*": "deny", "<absolute materialized diff path>": "allow"}`, generated with the same JSON serializer as the edit rule. Write the materialized diff with `mktemp` rather than to a predictable shared `/tmp` path. Add an `opencode debug agent` check that no broader external allow survives the merge.

### [low] plan-review-loop Phase 4 fallback wording contradicts the stop hook and the shared backend order
**Where:** `skills/plan-review-loop/SKILL.md:149` vs `hooks/stop-hook.sh:183` · **Lane:** contracts

The hook now says "on failure fall back to the next backend". Phase 4 still says "including the Codex liveness probe and watchdog — on backend failure, fall back to a subagent". That skips opencode and omits opencode's liveness rules. **Impact:** the two instructions the agent receives during a confirm round disagree, so the agent may skip a cross-model confirmation that was available. **Fix:** change Phase 4 to "including the Codex/opencode liveness probes and watchdog — on backend failure, fall back to the next backend".

### [low] The "RIGHT" watching example omits `--output-last-message`, so copying it produces no artifact
**Where:** `skills/codex-review/reviewer-backends.md:221` · **Lane:** correctness

Under the new output contract, Codex produces the artifact only through `--output-last-message "$REVIEW_FILE"`. The example shown as correct, `codex --sandbox read-only exec "$PROMPT" > "$OUT" 2>&1 < /dev/null`, drops that flag. **Impact:** an agent that copies the example gets a log and no review file, which counts as a backend failure, and Codex is wrongly skipped. **Fix:** use the full invocation in the example: `codex --sandbox read-only exec --output-last-message "$REVIEW_FILE" "$PROMPT" > "$OUT" 2>&1 < /dev/null`.

### [low] The reviewer is told to reproduce a template that contains a `## Disposition` heading
**Where:** `skills/codex-review/SKILL.md:107-109`, `:145` · **Lane:** contracts

Phase 3 now tells the reviewer to "Include the Phase 4 format" in the artifact it writes. That template ends with a `## Disposition` heading, but the same section says "The caller adds dispositions". **Impact:** reviewer-written artifacts may contain an empty or reviewer-filled Disposition section. That blurs the reviewer/caller ownership boundary the change introduces, and the caller can end up with two Disposition headings. **Fix:** tell the reviewer to stop after `## Findings` (plus limitations and verdict), and have the caller append `## Disposition`.

### [low] The Codex documentation link points to a domain that is not a known OpenAI Codex documentation host
**Where:** `skills/codex-review/reviewer-backends.md:76` · **Lane:** contracts

The link to "official output documentation" goes to `https://learn.chatgpt.com/docs/non-interactive-mode`. I could not verify it (no network). ## Verdict

**needs revision**: there are no critical or high findings. The medium findings cover misreported reviewer independence, an unenforced and unbaselined source-unchanged check, a watcher that can never exit, and over-broad filesystem read access. 6. Watching example missing file output — **ACCEPTED**, fixed in `14a45c6`: the full launch example includes `--output-last-message` and captures `$!`.
7. Disposition ownership — **ACCEPTED**, fixed in `14a45c6`: reviewer artifacts end with limitations and verdict; the caller appends disposition.

Official documentation host — **DECLINED**: the link was fetched successfully. `https://developers.openai.com/codex/noninteractive/` redirects to `https://learn.chatgpt.com/docs/non-interactive-mode`, whose output section documents `-o` / `--output-last-message`.
